# 固定分段栏的裁切与回弹修复

## 问题与原因

首页「周课表 / 今日课程 / 更新课表」和设置页「跟随系统 / 浅色 / 深色」共用 `SegmentedTabs`。
旧实现使用 Miuix `TabRow` 的横向滚动列表，同时监听滚动位置并强制 `scrollToItem(0, 0)`。
横向拖动和组件内部选中项滚动仍可改变视口，随后又被归零，形成视频中的裁切与回弹。

旧实现还用 `LocalConfiguration.screenWidthDp` 计算三个按钮的宽度，未扣除调用方的页面及卡片内边距。
设置卡片和其他窄容器的实际宽度小于整屏宽度，因此不能仅靠预留屏幕两侧边距解决。

修复前在 Android 15 模拟器中，对真实控件施加横向拖动：

- 「周课表」的可见宽度从 321px 缩为 222px，拖动回归断言失败。
- 280dp 父容器中，首项可见宽度 321px，末项仅 51px，完整等宽显示断言失败。
- 单纯点击切换的断言当时通过，说明只测试点击无法覆盖视频中的拖动问题。

## 改动

改用非滚动的 Compose `Row`，通过 `weight(1f)` 将父容器的剩余宽度分给每个选项。
删除横向列表状态、强制归零协程和按屏宽计算的固定宽度。
选中项仍为主题色填充，未选中项仍为透明底描边；没有横向位移动画。
大字体允许换行，并以行内最大内容高度统一按钮高度，最小触摸高度为 44dp。
通过 `selectableGroup` 和 `Role.Tab` 提供选中语义。

仓库进入修复时已有未完成合并。两侧界面改版内容相同，冲突处理保留了后续版本的更新课表、壁纸、作者与课程布局改动。

## 验证

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
.\gradlew.bat :app:connectedDebugAndroidTest
```

UI 测试需要已启动的 Android 模拟器或测试设备；本次使用 Android 15（API 35）模拟器。
在 320dp（840px / 420dpi）和约 411dp（1080px / 420dpi）两种窗口宽度下，6 项 UI 测试分别全部通过。
38 项单元测试通过，调试 APK 构建成功；Lint 无错误，保留 28 条警告及 11 条提示。
已查看两种宽度下的首页与设置页截图，按钮两端圆角、描边及间距完整。

新增 6 项测试：

1. 窄父容器中三个选项全部可见且等宽。
2. 连续切换两端及中间选项，逐帧检查位置和宽度。
3. 双向拖动并释放，检查拖动期间及释放后的边界。
4. 240dp 父容器、两倍字体，无文字溢出，按钮等高且触摸高度足够。
5. 完整首页的三页切换与更新页竖向滚动，栏位位置不变。
6. 完整设置页的系统、浅色、深色切换，栏位位置不变。

完整页面测试使用本机写入的虚构课程数据，不登录学校系统、不调用学校接口。
页面截图保存在模拟器 `/data/local/tmp/guangxiaoke-*.png`，可使用 `adb pull` 导出。

测试框架在本机 Android 37 模拟器上因 Espresso 的 `InputManager.getInstance` 兼容问题未能执行断言；这不计为控件复现或验证结果。
本次模拟器结果不能替代用户视频对应手机上的真机验收。
